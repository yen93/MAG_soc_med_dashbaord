System type: Static, no-build client-side web dashboard (HTML/CSS/vanilla JS
             ES modules). No server, no framework, no bundler.

--------------------------------------------------------------------------------
1. PURPOSE
--------------------------------------------------------------------------------
Scores My Adventure Group's (MAG) four public-facing channels — Instagram,
Website, Facebook, LinkedIn — on a 0-100 "health score" each, rolled up into
one overall MAG Social Health Score, with a per-channel category breakdown,
auto-generated strengths/gaps summary, recommendations, and a 6-month
sparkline history.

--------------------------------------------------------------------------------
2. FILE MAP
--------------------------------------------------------------------------------
index.html              Page shell. Renders a fixed "scanning" overlay
                         (#scan-overlay) on load, a hidden <main id="app">,
                         and loads js/app.js as an ES module.

css/styles.css          All styling: CSS custom-property design tokens
                         (--color-primary, --color-accent, grade colors),
                         scan-overlay animation states, hero layout with an
                         SVG gauge, responsive channel-card grid, category
                         progress bars, sparkline container, footer.

js/scoring.js           Pure scoring engine, no DOM/IO. Exports:
                           - CHANNEL_WEIGHTS, {INSTAGRAM,WEBSITE,FACEBOOK,
                             LINKEDIN}_WEIGHTS, BENCHMARKS, GRADE_BANDS
                             (all named constants, tunable without touching
                             formulas)
                           - gradeFor(score) -> {min,label,className}
                           - computeAllScores(metrics) -> full view model
                             { magOverall, magGrade, channels: {...} }
                         Internals: weightedAverage() skips null sub-scores
                         and renormalizes remaining weights (a channel
                         missing one input, e.g. FB reviews disabled, isn't
                         penalized or faked); rateScore() linearly scales a
                         raw metric against a benchmark target; growthScore()
                         maps % follower change to a 0-100 score centered on
                         50 at 0% growth; freshnessScore() maps days-since-
                         update to 0-100 between two day thresholds;
                         bookingPathScore() penalizes each extra click to
                         book/contact. buildInsights() auto-writes the
                         "what's strong / what needs work" summary and up to
                         3 recommendation lines from each channel's two
                         lowest-scoring categories, using per-category
                         template strings that interpolate real numbers from
                         metrics.json (e.g. "Posting cadence is light (4
                         posts in 30 days)..."). The three engagement-rate
                         formulas (Instagram/Facebook/LinkedIn) were fixed
                         2026-08-07: they used to default missing per-post
                         metrics to 0 inside the numerator while gating only
                         on "followers" being present, so a real follower
                         count with no engagement data produced a false,
                         confident "0% engagement / At Risk" instead of "No
                         Data". They now also require at least one real
                         engagement-volume field before computing a rate.

data/metrics.json       Raw input data, hand-maintained. One object per
                         channel: {platform, handle, url, lastUpdated,
                         raw: {...channel-specific fields...}, history: [
                         {date, score}, ...]}. meta.isPlaceholderData is now
                         FALSE: every field present under a channel's "raw"
                         is a real, sourced value verified 2026-08-07 (see
                         each channel's "_comment" and
                         update_logs/070826_2.txt for exact sources).
                         Fields that only exist inside a platform's private
                         analytics (Instagram/Facebook/LinkedIn Insights) or
                         a paid Lighthouse run are simply ABSENT from
                         "raw" rather than null placeholders — scoring.js's
                         weightedAverage() already renormalizes around
                         missing inputs, so this degrades a category to
                         "No Data" correctly. "history" was reset from a
                         fabricated 6-month trend to one real entry per
                         channel (Facebook has none yet, since it has no
                         scored categories at all) — sparklines/trend chips
                         stay hidden until a second real snapshot exists.

js/app.js                Entry point loaded by index.html. Drives the
                         #scan-overlay step animation (respects
                         prefers-reduced-motion by skipping straight to the
                         end state), wires the #scan-skip button, fetches
                         data/metrics.json, calls computeAllScores(), and
                         renders the hero gauge, four channel cards
                         (icon/handle, gauge, grade badge, category bars via
                         gradeFor() per category, auto-generated
                         summary/recommendations, a month-over-month trend
                         line, an SVG sparkline from each channel's
                         "history" array, and a footer with last-updated
                         date + a link to the live channel) into #app. Falls
                         back to a .data-error panel if the fetch fails or
                         the JSON is malformed. All gauge/sparkline color
                         classes (stroke-excellent, cat-fill.good, etc.) are
                         derived from gradeFor()'s className so channel
                         cards and category bars use the same 4-band
                         color language as the hero score. Also renders a
                         "N of 5 categories scored" coverage chip next to
                         every grade badge (hero + each channel card, via
                         coverageFor()/aggregateCoverage()) — added
                         2026-08-07 once real (partial) data made it clear a
                         grade built from 1 of 5 categories could otherwise
                         look identical to a fully-measured "Excellent".

package.json             { "type": "module" } only, so Node treats
                         js/scoring.js as an ES module for local testing.
                         Explicitly not required to host the site — there is
                         no build step and no runtime dependency list
                         (no node_modules, no lockfile).

.claude/settings.local.json   Local Claude Code permission allow-list
                         (WebFetch domains used while researching MAG's real
                         site and a reference audit tool). Not part of the
                         application; excluded from version control via
                         .gitignore.

3. SCORING MODEL (as implemented in js/scoring.js)
--------------------------------------------------------------------------------
Channel weights (equal, 25% each): Instagram, Website, Facebook, LinkedIn.

Instagram categories & weights:
  Profile Completeness 15% | Content Quality & Consistency 25% |
  Engagement 30% | Growth 15% | Hashtag & Discoverability 15%

Website categories & weights:
  Performance 20% | SEO Basics 20% | Content Freshness 15% |
  Conversion Clarity 25% | Trust Signals 20%

Facebook categories & weights:
  Page Completeness 20% | Posting Consistency 20% | Engagement Rate 30% |
  Review Rating 15% | Response Rate 15%

LinkedIn categories & weights:
  Company Page Completeness 20% | Posting Consistency 15% |
  Engagement Rate 30% | Follower Growth 15% | Content Relevance Mix 20%

Benchmarks driving the linear rate scores (BENCHMARKS in scoring.js):
  Instagram: 12 posts/mo, 50% video mix, 6% engagement rate, 15 hashtags/post
  Facebook:  8 posts/mo, 1% engagement rate
  LinkedIn:  8 posts/mo, 2% engagement rate
  Website:   full freshness score within 30 days, zero after 180 days

Grade bands (identical thresholds for every channel and the overall score):
  90-100  Excellent   75-89  Good   50-74  Needs Work   0-49  At Risk
  (missing/NaN score -> "No Data")

4. HOW TO RUN LOCALLY
--------------------------------------------------------------------------------
This is a static site with an ES module entry point, so it must be served
over http(s) — opening index.html directly via file:// will not load the
module script in most browsers. From this folder:
  npx serve .        (or any other static file server)
then open the printed localhost URL.

To complete the real-data picture: add the fields currently absent from
each channel's "raw" object in data/metrics.json, pulled from that
platform's own analytics — see update_logs/070826_2.txt for the exact
per-field checklist (what's missing, and where in Instagram Insights /
Meta Business Suite / LinkedIn Page analytics / a manual PageSpeed run to
find each one). Then update "lastUpdated" and append a new {date, score}
entry to "history" so the sparkline/trend chip has a second real point to
compare against.

5. KNOWN ISSUES / GAPS (as found 2026-08-07, updated same day once js/app.js
   was written and verified)
--------------------------------------------------------------------------------
1. [RESOLVED 2026-08-07] js/app.js was missing at initial review — index.html
   loaded it as the page's only script, and nothing else in the repo fetched
   data/metrics.json or rendered into #app, so the dashboard never
   progressed past the scanning overlay. js/app.js has since been written
   (see section 2 above) and verified end to end with a headless-browser
   pass: page loads -> scan overlay animates -> Skip button dismisses it on
   click -> hero + all 4 channel cards render with real category bars,
   summaries, recommendations and sparklines -> zero console/page errors.
2. [RESOLVED 2026-08-07] data/metrics.json was entirely placeholder data.
   Replaced with real, sourced values where publicly verifiable; unscoreable
   fields are absent rather than faked (see section 2 above and
   update_logs/070826_2.txt). Residual gap: most channels are still
   low-coverage — e.g. Instagram and LinkedIn each currently have only 1 of
   5 categories scored (their "Excellent" grades reflect that one category,
   not full-channel health) — now visibly flagged in the UI by the coverage
   chip rather than hidden. Facebook has 0 of 5 categories scored (correctly
   shows "No Data"). Completing this requires the account owner pulling
   numbers from each platform's private analytics.
3. No automated tests exist for the scoring functions in js/scoring.js,
   despite them being pure and straightforward to unit test. (js/app.js's
   rendering logic was verified manually via a headless-browser pass rather
   than an automated test suite — no test framework is set up in this repo.)
4. No README in the repo describing setup/run steps (this as-built file and
   the inline code comments are currently the only documentation).
5. This repo's git history starts with the initial commit that added this
   as-built file — no prior version history exists for the files above,
   which were authored in an earlier working session.
